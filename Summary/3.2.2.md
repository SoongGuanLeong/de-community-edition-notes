## 1️⃣ Config & Tuning

```scala
spark.conf.set("spark.sql.autoBroadcastJoinThreshold", "-1")
spark.conf.set("spark.sql.analyzer.failAmbiguousSelfJoin", "false")
spark.conf.set("spark.sql.shuffle.partitions", "4")
```

* **Broadcast join disabled**: Good for large tables; if either table is small (<1-2GB), consider using `broadcast()` for speed.
* **Shuffle partitions = 4**: OK for small data, but scale with data size (~100MB per partition is a good rule of thumb).
* **Analyzer setting**: only disable if self-joins are safe; otherwise could mask logic errors.

## 2️⃣ Reading Data

* You are using `.option("inferSchema", "true")`. For production, **explicit schema** is faster and safer.
* Filtering `user_id IS NOT NULL` is good early to reduce shuffle and memory.

---

## 3️⃣ Aggregation & Caching

```scala
val eventsAggregated = spark.sql("""
  SELECT user_id, device_id, 
         COUNT(1) as event_counts, 
         COLLECT_LIST(DISTINCT host) as host_array
  FROM events
  GROUP BY user_id, device_id
""").cache()
```

* **`cache()`**: Fine for < 5GB.
* **Alternative**: If data is bigger, consider `persist(StorageLevel.MEMORY_AND_DISK)` to avoid OOM.
* Using `COLLECT_LIST(DISTINCT host)` is expensive; consider `approx_distinct` or deduplicate first if possible.

---

## 4️⃣ Joins & Aggregations

```scala
val usersAndDevices = users
  .join(eventsAggregated, "user_id")
  .groupBy("user_id")
  .agg(
    max("event_counts").as("total_hits"),
    collect_list("device_id").as("devices")
  )
```

* **Join pattern**: Prefer `broadcast(eventsAggregated)` if small.
* `groupBy` on `user_id` only, fine. Avoid grouping by large arrays/structs.

```scala
val devicesOnEvents = devices
  .join(eventsAggregated, "device_id")
  .groupBy("device_id", "device_type")
  .agg(
    collect_list("user_id").as("users")
  )
```

* **Same advice**: Use broadcast if `eventsAggregated` is small.
* Check skew: if some devices have massive numbers of users, consider **salting** to avoid partition skew.

## 6️⃣ Explain / Performance

* **Goal**: minimal shuffle + avoid wide joins on big tables.

### ⚡ Recommendations

1. **Explicit schema** instead of `inferSchema`.
2. Pre-deduplicate hosts for `COLLECT_LIST(DISTINCT host)` before aggregation to reduce shuffle.
3. Tune `spark.sql.shuffle.partitions` according to dataset size.

   * Small dev: 4-10
   * Medium: 200-500
   * Large (>10GB): 2000+
4. Consider **bucketed joins** if users & devices are repeatedly joined on same keys.
5. Always monitor **stage skew** and partition sizes with `.rdd.mapPartitions(_.size).collect()` if needed.
6. Use `.take(n)` or `.show(n)` for debug; never `.collect()` in production.
