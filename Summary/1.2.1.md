# 🔥 Core Principle: Idempotency Is Non-Negotiable

> A pipeline must produce the same result no matter:

* When it runs
* How many times it runs
* Whether it is backfilled

If it doesn’t → it is broken.

This is senior-level engineering thinking.

---

# 🧠 Why This Matters in Your Spark + Iceberg Project

You are building:

Kafka → Spark → Iceberg → BI

If not idempotent:

* Backfills will change numbers
* Bronze vs Silver mismatch
* BI dashboards fluctuate
* Trust collapses

And the worst part?

It won’t throw errors.

Silent data corruption is worse than system crashes.

# 🚨 Major Anti-Patterns Identified

Let’s convert them into strict rules for your project.

---

## 1️⃣ NEVER Use `INSERT INTO` for Transform Layers

Bad:

```
INSERT INTO silver.table
SELECT ...
```

Why?

* Appends duplicate records
* Not idempotent
* Breaks backfills

Correct patterns:

* `MERGE INTO`
* `INSERT OVERWRITE`
* Snapshot replace
* Deterministic partition overwrite

In Iceberg:

```
MERGE INTO target
USING source
ON ...
WHEN MATCHED THEN UPDATE
WHEN NOT MATCHED THEN INSERT
```

---

## 2️⃣ Avoid “Latest Partition” Logic

Bad:

```
SELECT * FROM table WHERE date = max(date)
```

Why?

* If late data arrives → result changes
* If backfill → inconsistent

Correct:

Always operate on deterministic partitions.

---

## 3️⃣ No Unbounded Windows Without End Condition

If you do:

```
WHERE event_time >= '2024-01-01'
```

Without upper bound:

Result changes every day.

Correct:

Always define window:

```
WHERE event_date = '2024-01-05'
```

Or incremental bounded load.

---

## 4️⃣ Triggers Must Align With Data Readiness

Streaming jobs that trigger too early:

* Process partial Kafka batch
* Write incomplete snapshot
* Next run writes different result

Use:

* Watermarks
* Deterministic batch intervals
* Data availability checks

# 🚀 How This Applies to Your Architecture

## Bronze

Append-only.
Never update.
Partition by ingestion_date.
Idempotent because raw events immutable.

---

## Silver

Use:

MERGE INTO

Keys:

entity_id + effective_date

Maintain:

* start_date
* end_date
* is_current

Never use:

INSERT INTO without overwrite.

---

## Gold

Use deterministic aggregation:

Partition by date.
Overwrite partition.

Never accumulate.
