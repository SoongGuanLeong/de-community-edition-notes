## 1️⃣ Reading & Preparing Data

```python
events = spark.read.option("header", "true").csv("/home/iceberg/data/events.csv") \
    .withColumn("event_date", expr("DATE_TRUNC('day', event_time)"))

devices = spark.read.option("header","true").csv("/home/iceberg/data/devices.csv")

df = events.join(devices, on="device_id", how="left") \
    .withColumnRenamed('browser_type', 'browser_family') \
    .withColumnRenamed('os_type', 'os_family')
```

**Best practices:**

* Always avoid `.collect()` on large datasets; use `.show()` or `.take()`.
* Precompute derived columns like `event_date` for partitioning and bucketing.

## 2️⃣ Sorting & Repartitioning

```python
sorted = df.repartition(10, col("event_date")) \
    .sortWithinPartitions(col("event_date"), col("host")) \
    .withColumn("event_time", col("event_time").cast("timestamp"))

sortedTwo = df.repartition(10, col("event_date")) \
    .sort(col("event_date"), col("host")) \
    .withColumn("event_time", col("event_time").cast("timestamp"))
```

* `.sortWithinPartitions()` → sorts **inside each partition**; no shuffle, efficient.
* `.sort()` → global sort; triggers a full shuffle; very slow at scale.
* Check plans with `.explain()`. Look for `Exchange` → indicates shuffle.

✅ **Tip:** Always use `sortWithinPartitions` unless a full global ordering is required.

## 3️⃣ Iceberg Tables Setup

```sql
CREATE DATABASE IF NOT EXISTS bootcamp;

DROP TABLE IF EXISTS bootcamp.events;
DROP TABLE IF EXISTS bootcamp.events_sorted;

CREATE TABLE bootcamp.events (
    url STRING, referrer STRING, browser_family STRING, os_family STRING,
    device_family STRING, host STRING, event_time TIMESTAMP, event_date DATE
) USING iceberg
PARTITIONED BY (years(event_date));

CREATE TABLE bootcamp.events_sorted (...) USING iceberg PARTITIONED BY (years(event_date));
CREATE TABLE bootcamp.events_unsorted (...) USING iceberg PARTITIONED BY (year(event_date));
```

**Partitioning tips:**

* Iceberg supports functional partitioning (`years(event_date)`) → efficient pruning.
* Keep partition columns coarse enough (year/month) to avoid too many small files.

## 4️⃣ Writing Tables

```python
start_df = df.repartition(4, col("event_date")) \
    .withColumn("event_time", col("event_time").cast("timestamp"))

first_sort_df = start_df.sortWithinPartitions(col("event_date"), col("browser_family"), col("host"))

start_df.write.mode("overwrite").saveAsTable("bootcamp.events_unsorted")
first_sort_df.write.mode("overwrite").saveAsTable("bootcamp.events_sorted")
```

**Best practices:**

* Repartition **before writing** to control file sizes and avoid small files.
* Use `.sortWithinPartitions()` for better compression and query speed.
* `.mode("overwrite")` → idempotent writes (safe SCD-like pattern for batch jobs).

## 6️⃣ Key Takeaways / Spark + Iceberg Patterns

1. **Partitioning**: coarse grain (year/month) for pruning, fine-grain sorting for query efficiency.
2. **Avoid global sort** (`sort()`) → huge shuffle, slow.
3. **Use `.sortWithinPartitions()`** → orders data locally, minimal shuffle.
4. **Repartition wisely** → balance parallelism vs file sizes.
5. **Idempotent writes** → overwrite or merge for safe incremental updates.
6. **Check storage stats** → ensure small files problem is mitigated.
7. **Explain plans** → detect unwanted shuffles.
