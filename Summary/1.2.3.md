# 🧠 Core Ideas Extracted

---

## 1️⃣ Snapshot → Interval Transformation

You already had:

```
(player_name, current_season)
```

Now you compress that into:

```
(player_name, start_season, end_season)
```

Where:

* Each row represents a stable state
* Only changes create new rows

This reduces row count dramatically.

This is dimensional compression.

---

## 2️⃣ Change Detection via LAG

This is critical:

```
LAG(scoring_class)
LAG(is_active)
```

Then:

```
CASE WHEN changed THEN 1 ELSE 0
```

This is:

State transition detection.

In Spark this becomes:

```python
from pyspark.sql.window import Window
from pyspark.sql.functions import lag
```

This pattern is universal.

---

## 3️⃣ Streak Identifier (Brilliant Pattern)

This line:

```
SUM(change_indicator)
OVER (PARTITION BY player_name ORDER BY current_season)
```

Creates a streak group id.

This is extremely powerful.

It means:

* Each time a change happens → increment group
* All identical consecutive states share same streak id

This avoids:

Complex procedural logic.

It is pure SQL windowing.

---

## 4️⃣ Group By Streak → Create Intervals

```
MIN(current_season) AS start_season
MAX(current_season) AS end_season
```

Now each streak becomes:

One SCD Type 2 row.

Clean.
Deterministic.
Idempotent.
