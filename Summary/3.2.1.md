## 1️⃣ Spark Session Context

| Server                                        | Notebook                                                           |

| Fresh Spark session every run (safe for prod) | Persistent Spark session; must manually `.unpersist()` to free RAM |

* **Caching:** Only cache if data fits in RAM; use materialized/staging table if spill occurs.

---

## 2️⃣ Caching vs Broadcast Join

| Aspect   | Caching            | Broadcast Join                     |
| -------- | ------------------ | ---------------------------------- |
| Stores   | Partitioned in RAM | Full table in RAM to all executors |
| Use case | Big tables         | Small tables (< several GB)        |

* **Optimization:** `spark.sql.autoBroadcastJoinThreshold` or `broadcast(df)`.

---

## 3️⃣ UDF Choices

* **Scala UDF:** Native, compiled; use for massive datasets & UDAFs.
* **Python UDF:** Easier, flexible; slower for huge data, avoid for massive aggregation.

---

## 4️⃣ API Selection

| API             | Use Case                                          |
| --------------- | ------------------------------------------------- |
| SparkSQL        | Collaboration, ad-hoc queries                     |
| DataFrame       | Python pipelines, flexible                        |
| Dataset (Scala) | Best performance, full type safety, UDAFs support |

---

## 5️⃣ File & Shuffle Best Practices

* **Parquet:** Use run-length encoding, compress well.
* **Sorting:** Prefer `.sortWithinPartitions()` over global `.sort()`.
* **Partitioning:** Repartition to avoid small files; aim ~100MB/partition.
* **Shuffles:** Minimize; high-volume shuffles → major performance hit.

---

## 6️⃣ Spark Tuning Rules

| Component                      | Recommendation                                                         |
| ------------------------------ | ---------------------------------------------------------------------- |
| Executor RAM                   | Start small; test incrementally (do not default 16GB)                  |
| Driver RAM                     | Only increase for `collect()` or complex plan                          |
| Shuffle partitions             | Default 200; tune based on size (~100MB/partition)                     |
| AQE (Adaptive Query Execution) | `spark.sql.adaptive.enabled = True`; unnecessary if data is not skewed |

---

### ⚡ Key Takeaways

1. Avoid global `.sort()`; use local `.sortWithinPartitions()`.
2. Cache only when you benefit from RAM-resident data.
3. Scala for heavy compute; Python for flexibility.
4. Partition & bucket tables to minimize shuffles.
5. AQE & broadcast joins are your friends, but only when relevant.
6. Always monitor partitions, skew, and file sizes after writes.
