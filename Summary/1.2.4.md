# 🔥 What This Pattern Is

You are doing:

```
players_scd (2021)
        +
players (2022 snapshot)
        →
players_scd (2022)
```

This is **incremental dimension evolution**.

No full rebuild.
No window functions.
Pure set-based logic.

---

# 🧠 Core Architecture Pattern

You split the world into 4 groups:

---

## 1️⃣ Historical Records (Already Closed)

```
end_season < 2021
```

These never change again.

Carry forward as-is.

---

## 2️⃣ Unchanged Records (Extend Interval)

If:

```
scoring_class same
AND is_active same
```

Then:

```
start_season stays
end_season becomes 2022
```

This is interval extension.

This is the cheapest possible update.

---

## 3️⃣ Changed Records (Close + Open)

If state changed:

You create:

1. Old record (closed at 2021)
2. New record (opened at 2022)

This is textbook SCD Type 2.

---

## 4️⃣ Brand New Entities

If player didn’t exist in 2021:

Insert new row:

```
start_season = 2022
end_season = 2022
```

---

# 🔥 Why This Is Advanced

Notice:

There is no window.
No lag.
No streak computation.

Because you are no longer reconstructing history.

You are maintaining it incrementally.

This is the difference between:

Batch reconstruction
vs
Dimensional maintenance
